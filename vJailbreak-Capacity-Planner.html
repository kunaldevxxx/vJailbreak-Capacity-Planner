RDM Disk Migration — Prerequisites & Constraints
Applies to any VM below using an RDM/Cinder-adoption strategy. Source: vJailbreak docs, Guide → "Migrating RDM Disk".
  • Platform version: RDM disk migration requires PCD ≥ July 2025 (2025.7). It is not supported on plain OpenStack.
  • Multi-attach / SAN multipath (shared pRDM for Windows failover clusters) additionally requires PCD ≥ October 2025 (2025.10) with patched libvirt/QEMU, plus a Cinder volume type with multi-attach enabled.
  • Cold migration only: RDM-backed VMs can only use migrationStrategy.type: cold — no warm or live migration.
  • Owner-VM grouping (VALIDATE_RDM_OWNER_VMS, default true): every VM sharing the same RDM disk must be included in the same migration plan.
  • Manual step, not scriptable: in VMware, the VM must be powered off and the RDM disk detached (leave "Delete files from storage" unchecked) before a migration plan can be created.
  • Multi-IP / Cluster IP Error Workaround: If migration fails with "Failed to reserve port for VM: multiple user-assigned IPs not supported for an interface", remove the secondary Cluster IP from the migration form, trigger the migration, and re-add the Cluster IP on the PCD side using openstack port set --fixed-ip before target port attachment.
  • Rollback caution: once an RDM disk is Cinder-managed, never delete the volume directly — use openstack volume delete <volume-id> --remote to unmanage it without touching the underlying SAN LUN.
